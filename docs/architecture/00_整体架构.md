# APM 整体架构图

> 最后更新：2026-07-04

> 当前交接快照、未完成项和新电脑接手步骤见 `../PROJECT_HANDOFF.md`。

## 2026-07-07 优化更新

- 构建基建：新增 `build-logic` included build 提供 `com.apm.android-library` convention plugin，20 个库模块的 compileSdk/minSdk/Java 版本收敛到一处；根构建与 smoke consumer 统一走 version catalog 插件别名；发布产物带完整 POM 元数据与可选签名。
- 分发管线线程模型重构：`Apm.emit` 在调用线程只捕获时间戳/线程名/业务上下文快照，事件构建、聚合、限流、脱敏全部推迟到 `apm-dispatcher` worker 线程；worker 以有界队列（2048，满丢弃计数）+ 批量 drain（≤32 条）驱动 `EventStore.appendBatch` 单事务落盘。
- 限流桶 LRU 上限 256；`RetryingApmUploader` 退避改为调度器重投不阻塞队列；`PersistentUploadWorker` 单一重试权威 + 空闲清理（retry≥10 或 7 天过期）。
- 多进程 IPC 合批：`maxLinesPerFile` 生效，普通事件按行数/500ms 定时合批发布，critical 事件仍立即单文件发布。
- 共享线程设施 `ApmExecutors`（命名 daemon 线程、默认最低优先级），核心管线执行器均已迁移。
- SDK 自监控新增 `internalErrorCount`：各模块降级处理的异常经 `Apm.recordInternalError` 计数并随健康报告上报。

## 2026-07-04 可靠性基线

- 默认数据路径为 `Apm.emit → ApmDispatcher → SQLite PendingEventStore → PersistentUploadWorker → BatchApmUploader`。
- SQLite 行保存可逆的 `ApmEventCodec` payload，完整批次上传成功后才确认删除，失败和进程退出均保留待重放。
- Crash 等关键事件走同步落盘入口；非上传进程通过同步 IPC 文件发布交给上传进程，普通事件仍在单线程 dispatcher 中异步处理。
- 多进程协调使用 `.tmp` 写入、`.ipc` 发布的事件文件，扫描端只消费完整发布的 ready 文件。
- 默认 HTTP endpoint uploader 开启 Gzip，宿主可通过 `ApmConfig.enableHttpGzip` 显式关闭。
- `FpsModule` 延迟到 Activity 生命周期主线程创建 `FpsMonitor`，避免后台提前构造 `Choreographer`。
- `apm-io`、`apm-crash`、`apm-memory` JNI 目标按 16KB 页面大小链接对齐。
- 聚合、栈指纹、上传队列均有硬上限；关闭时有界排空已接收任务并释放 store/uploader。
- 动态配置、灰度、多进程协调、SDK 自监控与自动降级已经接入模块启动流程。
- 构建栈为 Gradle 8.13、AGP 8.13.2、Kotlin 2.2.21、JDK 21，发布物保持 Java 11 字节码。
