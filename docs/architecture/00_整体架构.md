# AndroidAPM 整体架构

> 同步日期：2026-07-11｜以当前源码、构建配置与测试为准

## 1. 系统边界

AndroidAPM 是端上 SDK，不是完整托管 APM 产品。

仓库内：

- 15 个 Android 监控模块
- 统一事件模型和上下文
- 分发、限流、可选聚合与可选 PII 脱敏
- SQLite durable outbox、File 兼容存储
- HTTP/Logcat/自定义 uploader
- 可选多进程文件 hand-off
- SDK 自监控、独立本地诊断日志和自动降级
- 手动 Trace API、OTel-compatible Map
- ASM Gradle 插件和示例应用

仓库外：

- 生产 Collector、鉴权、租户
- 数据查询、聚合、告警、Dashboard
- Native 符号化服务
- 服务端事件去重与幂等
- 外部 Maven 仓库

## 2. 构建拓扑

```text
24 build units
├─ 22 root subprojects
│  ├─ 4 foundation: model / core / storage / uploader
│  ├─ 15 monitoring modules
│  ├─ 2 extensions: trace / otel-exporter
│  └─ 1 sample app
└─ 2 included builds
   ├─ apm-plugin
   └─ build-logic
```

所有监控模块通过 `api(project(":apm-core"))` 暴露统一接入入口，并通过 `apm-model` 构造事件。`apm-core` 依赖 storage，API 暴露 model/uploader。`apm-otel-exporter` 只依赖 model；`apm-plugin` 只参与编译期。

## 3. 运行时主链路

```text
Monitor / Trace
  │
  ├─ Apm.emit
  │    caller captures timestamp, threadName, bizContext snapshot
  │
  ├─ ApmContext
  │    main/uploader process -> dispatcher
  │    child process + coordination -> IPC file hand-off
  │
  ├─ ApmDispatcher queue
  │    ArrayBlockingQueue capacity 2048
  │    offer only; overflow drops and self-monitors
  │
  ├─ worker batch (first + drainTo, max 32)
  │    resolve lazy event
  │    -> optional aggregate
  │    -> rate limit (ERROR/FATAL bypass)
  │    -> optional PII sanitize
  │    -> EventStore.appendBatch
  │
  ├─ SQLiteEventStore
  │    schema v2 / WAL / capacity 50,000
  │    priority eviction / reversible payload
  │
  ├─ PersistentUploadWorker
  │    readPending -> upload once
  │    success: deletePending
  │    failure: markRetry -> backoff
  │
  └─ HttpApmUploader / custom uploader
       batch POST / optional Protobuf / default Gzip
       2xx success / 429 or 503 Retry-After
```

## 4. 关键事件

`Apm.emitCriticalSync` 立即构建事件并到达本地 durable hand-off point：

- uploader process：同步 `store.append`，随后 signal worker
- 非 uploader process 且启用协调：同步发布单独 IPC 文件

该路径不等待网络。若使用 `StorageType.FILE`，只能同步写非 durable ring buffer，无法获得 restart replay/acknowledged delete 语义。

## 5. 交付语义

当前语义是 acknowledged at-least-once：

- 只有 uploader 返回完整批次成功才删除 outbox 行
- 失败保留并增加 retry count
- 本地指数退避与服务端 `Retry-After` 取较大值
- retry ≥ 10 或事件时间超过 7 天后清理
- 进程重启后 worker 从 SQLite 重放

不保证 exactly-once：

- `ApmEvent` 没有 eventId/idempotency key
- 服务端成功但客户端未收到响应时会重发
- 当前只有单 worker 所有者语义，没有 claim/lease
- 在增加多 worker/cross-process upload 前必须先设计领取、续租、过期和恢复

## 6. 生命周期

```text
Apm.register before init
  -> module retained

Apm.init
  -> create independent diagnostics + logger
  -> create store/uploader/limiter/aggregator/sanitizer/self-monitor
  -> create dispatcher
  -> optional ProcessEventCoordinator
  -> start every registered module that passes process/dynamic/gray filters

Apm.register after init
  -> atomic duplicate-name check
  -> initialize and start immediately when filters allow

Apm.stop
  -> state=null, reject new emits
  -> stop self-monitor/coordinator
  -> module.onStop
  -> drain dispatcher with timeout
  -> flush aggregation residue
  -> stop worker/uploader
  -> close store
```

模块启动受三层过滤：`ProcessStrategy`、`DynamicConfigProvider`、`GrayReleaseController`。自动降级可以根据 SDK 健康报告停止低优先级模块，但不会在当前进程内自动重新启动。

## 7. 多进程

多进程协调默认关闭。开启时主进程为 uploader process：

```text
child process event
  -> buffer on apm-ipc-write
  -> flush at 100 lines or 500 ms
  -> write unique .tmp
  -> rename to .ipc
  -> main process scan every 5 s
  -> decode complete ApmEvent
  -> dispatcher
```

critical 事件绕过缓冲并同步发布。`.ipc` 文件 5 分钟过期；遗留 `.tmp` 也按超时清理。rename 失败会 copy 到 ready 文件后删除 temp，这一 fallback 不应被解释成跨文件系统事务保证。

## 8. 线程与执行器

| 线程/执行器 | 作用 | 优先级意图 |
|---|---|---|
| `apm-dispatcher` | 解析、聚合、限流、脱敏、批量落盘 | 后台管线；当前为命名 daemon Thread |
| `apm-persistent-upload` | outbox 顺序上传与重试 | background |
| `apm-aggregation` | 过期聚合窗口 flush | background |
| `apm-self-monitor` | SDK 健康报告/auto-throttle | background |
| `apm-diagnostics-writer` | 独立诊断 JSONL 落盘 | background |
| `apm-ipc-write` / `scan` | IPC 合批发布/扫描 | background |
| 模块采样线程 | Memory/GC/Thread/Battery 等 | background 或 measurement |
| `apm-anr-*` | Watchdog/SIGQUIT 分析 | measurement |
| slow-method sampler | 主线程栈采样 | measurement |

`ApmExecutors` 统一 daemon、线程名和两级优先级。`apm-uploader` 无法依赖 core，因此保留模块内执行器和 `UploaderLogger`。

## 9. 资源保护

- dispatcher queue：2048
- dispatcher drain：32
- SQLite rows：50,000
- RateLimiter bucket LRU：256
- non-durable uploader queue：500
- aggregation bucket/sample：有硬上限
- stack fingerprint cache：有硬上限
- IPC file batch：100 行
- event payload：2 MiB
- event map：4096 entries
- diagnostics memory/queue：200 / 256 records，且各自最多 4 MiB
- diagnostics files：3 × 512 KiB

发生过载时优先丢低价值事件并记录自监控，而不是让资源无界增长。

## 10. 配置默认行为

| 能力 | 默认 |
|---|---|
| SQLite durable outbox | 开 |
| HTTP Gzip | 开（只有 HTTP endpoint 时生效） |
| Self monitoring / auto-throttle | 开 |
| Aggregation | 关 |
| PII sanitization | 关 |
| Multi-process coordination | 关 |
| Native crash | 关 |
| Hprof / fork dump | 关 |
| Endpoint | 空，使用 Logcat |

“实现存在”不等于“默认开启”；生产配置必须显式评审隐私、采样、进程、网络和高风险 Native/Hprof 能力。

## 11. 监控层接入分类

自动/生命周期驱动：Crash、ANR、Memory 周期采样、Launch、FPS、Thread、GC、Render。

宿主接线：Network、SQLite、IPC、WebView、Battery 的 WakeLock/GPS/Alarm、IO stream wrapper、Launch 精细阶段。

编译期接线：Slow Method ASM 插件。

当前声明但未完成通用自动实现：Binder hook、WebView auto-register、thread-pool backlog、Render overdraw/draw time。

## 12. 自监控与独立诊断

`SdkSelfMonitor` 记录 emit、drop、queue size、upload latency、internal errors、诊断队列丢弃和诊断文件失败。健康报告可驱动 `AutoThrottle`：高丢弃率或高延迟时停用低优先级模块；极高丢弃率再停用部分 normal 模块。

自监控事件仍走普通管线，因此极端拥塞下可能被限流/丢弃。详细 SDK 错误另写独立的 Logcat + 内存环 + app-private 滚动 JSONL，不依赖 dispatcher/outbox/uploader；journal 按 Android 进程隔离，聚合导出会合并所有进程。内存和写队列同时受条数/字节双预算约束，冷却期间先等待再出队，读写失败分开统计。`ApmDiagnostics` 提供同步兼容及 executor 异步读取/导出、当前进程清理和显式全进程清理；诊断包默认不自动上传。
