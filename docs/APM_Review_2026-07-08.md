## 3. 当前仍需关注的问题

### 3.1 数据交付一致性

SQLite outbox 能够承受进程重启并在成功确认后删除事件，但不能单独保证 exactly-once。后续如果接入生产采集端，应同时设计：

1. 稳定事件 ID；
2. 服务端幂等写入；
3. 多消费者并发下的 claim/lease；
4. 重放、死信与数据保留策略。

### 3.2 配置开关与真实能力

部分配置项是预留接口，并不等于对应运行时能力已经完成。当前需要继续明确标注的项目包括：

- 通用 Binder 自动 Hook；
- WebView 自动注册；
- 线程池积压与线程泄漏检测；
- Render 过度绘制与 draw-time 采集。

### 3.3 真机与生产环境验证

Robolectric、JVM 单测和构建链能够覆盖大量契约，但以下场景仍应保留真机矩阵：

- native SIGQUIT/ANR 与崩溃信号；
- 多进程 IPC 与异常退出恢复；
- OEM 定制系统下的 `/proc`、`ApplicationExitInfo` 与系统限制；
- 网络弱网、服务端限流和长时间离线后的 outbox 恢复。

## 4. 评审结论

2026-07-08 的主要工程治理项已经进入当前源码；历史工作区噪声不再作为当前风险。项目现阶段最重要的边界不是“再增加模块数量”，而是把已有采集能力与生产采集端、幂等交付、设备矩阵和可观测运维闭环连接起来。
