# AndroidAPM 优化记录（2026-07-08）

> 文档性质：历史优化归档。原记录中的“未提交/待确认”状态已按 2026-07-10 本地源码重新核对。当前状态总览见 [`Android_APM_项目文档.md`](Android_APM_项目文档.md)。

## 1. 优化目标

本轮优化聚焦 SDK 内部线程治理，目标是减少分散创建的线程和执行器，统一命名、异常隔离与生命周期管理，同时不破坏模块依赖边界。

## 2. 已落地内容

以下修改已由提交 `3c27ff9`（`Refactor: Unify SDK thread management`）进入 `develop` 当前源码：

- 在 `apm-core` 中建立共享 `ApmExecutors`；
- 将能依赖 `apm-core` 的模块迁移到共享执行器；
- 为后台任务保留具名线程与异常保护；
- 为关键线程治理契约增加测试；
- 保持 `apm-uploader` 的依赖方向，不为了复用而反向依赖 `apm-core`。

因此，旧记录中“修改未提交、等待确认后提交”的描述已经失效。

## 3. 有意保留的边界

### 3.1 `apm-uploader` 的模块内执行器

`apm-uploader` 位于核心上传链路的底层，不能访问 `apm-core`。它继续使用模块内执行器，并通过注入的 `UploaderLogger` 记录异常。这是依赖边界选择，不是遗漏迁移。

### 3.2 Dispatcher 专用工作线程

`ApmDispatcher` 使用专用有界队列工作循环处理批量事件。该线程承担队列消费语义，不能简单替换为无状态的公共线程池任务。后续若调整，应先保持顺序、背压与关闭语义的契约测试。

## 4. 当前复核重点

- 新增 SDK 后台任务时，优先通过 `ApmExecutors` 创建；
- 降级并吞掉的异常应调用 `Apm.recordInternalError(tag, error)`；
- 新执行器必须有明确的线程命名、队列上限、拒绝策略和关闭方式；
- 涉及 native 回调、Binder 回调或系统回调时，确认不在调用方主线程执行重活；
- 真机验证线程增长、ANR 信号与多进程退出后的资源释放。

## 5. 结论

线程治理优化已提交并成为当前实现的一部分。后续工作的重点是守住统一执行器规则和有界队列契约，而不是继续做一次性机械迁移。
